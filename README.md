# 温故 Wengu

**因材施教，人人可得。**

温故是一个开源的学习平台：把任何学习材料变成看得见、能互动、记得住的内容。AI 可视化负责理解和编码，间隔重复负责长期保持。名字取自《论语》"温故而知新"。

## 愿景

教育的终极理想是因材施教。过去的个性化学习只能调整固定内容的顺序和进度，现在内容本身可以为一个人生成。温故要了解的"材"有三项：

- **你已经会什么**：哪些掌握了，哪些快忘了，哪些总是错。
- **什么讲法对你有效**：由你自己的记忆数据判断，不靠学习风格测试。
- **你的目标和时间**：备考和长期学习的内容与节奏不同。

## 原则

| 原则 | 含义 | 因此不做 |
|---|---|---|
| 效果优先于时长 | 衡量记住和理解了多少 | 打卡焦虑、推送轰炸、为留存设计的游戏化 |
| 正确优先于丰富 | 生成内容可追溯来源、可纠错 | 没有来源的生成内容 |
| 以证据为准 | 只用认知科学支持的方法 | 流行但没有依据的做法 |
| 本地优先 | 数据在用户设备上，离线可用，同步可选 | 强制登录，数据只存云端 |
| 来去自由 | 导入 Anki 卡组，随时带进度导出 | 私有格式和数据锁定 |
| 用户掌控 | 安排可解释，内容可修改，模型可选择 | 黑箱推荐，无法关闭的 AI 功能 |
| 开源 | 全部功能代码公开，收费的只是托管服务 | 把核心功能留在闭源付费版 |
| 美观和速度是功能 | 操作即时响应，界面克制 | 拖慢复习的华丽效果 |

复习、浏览、编辑必须完全离线可用。生成功能可以联网，并支持自带密钥或本地模型。

## 范围

- 兼容 Anki 卡组（`.apkg` 的导入和导出，含复习记录）。
- 不兼容 Anki 插件，不接入 AnkiWeb 同步。
- 不复用 Anki 的代码。

## 里程碑

| 里程碑 | 交付 | 完成标准 |
|---|---|---|
| M0 技术验证 | 卡组导入原型，生成可视化原型 | 三副热门卡组导入不丢内容，排期与 Anki 的 FSRS 一致，一个可视化达到可展示质量 |
| M1 自用版 | 桌面端复习器：导入、复习、浏览编辑、导出 | 作者连续两周只用它复习，翻卡响应在 100 毫秒内 |
| M2 公开发布 | 手机端、可选同步、文档 | 100 个外部用户连续 30 天每天复习 |
| M3 可视化讲解 | 答错时提供生成的讲解，单一学科 | 看过可视化的卡片记忆保持率明显更高 |
| M4 从材料生成 | 上传教材生成知识点和呈现方式 | 只靠上传的材料学完一个章节 |
| M5 因材施教 | 按个人数据选择讲法和节奏 | 个性化效果好于统一默认方案 |
| M6 内容库 | 分享和改进可视化内容 | 用户贡献的内容超过官方生成的 |

核心假设是"可视化能让人记得更牢"。M0 之后先用二十张卡做一次粗糙的对照实验，再决定后续投入。

## 架构要点

- **核心单位是知识点**，卡片只是知识点的一种呈现方式。数据模型从 M1 起就按此设计。
- **三层结构**：内容层（多种呈现方式）、记忆层（FSRS 对知识点排期）、生成层（AI 生成可保存、可分享的组件）。
- **AI 生成的可视化是代码**，不是由固定组件渲染的配置。形式不受模板限制，设计变量（颜色、字体、间距）只作为推荐风格提供，不强制。
- **生成的组件在沙箱里运行**：隔离的 iframe，不能联网，不能读取应用的数据和存储。可用的库由应用预置并注入。
- **组件和应用通过一套小的消息接口通信**：应用传入知识点数据、主题和模式，组件传回就绪、尺寸变化和答题结果。答题结果进入排期。
- **复习路径上没有网络和生成**：生成在后台完成并缓存，数据库放在后台线程。
- **生成后自检**：在无界面的沙箱里运行，检查报错并截图复核，通过的才保存。

## 技术选型

- TypeScript、React、Vite，3D 用 three.js，以 WebGL2 为基准。
- 先做网页应用，之后用 Electron 打包桌面端。开发和自检都以 Chromium 为基准。
- 手机端到 M2 再定，届时生成的组件还要能在 Safari 内核上运行。
- 本地存储用 SQLite（浏览器中用 WebAssembly 版本）。
- 排期用 FSRS 官方的开源 TypeScript 实现。
- AI 走统一的接口层，支持自带密钥。

## 代码结构

- `packages/core`：数据模型和排期，不依赖界面。
- `packages/anki`：`.apkg` 的导入和导出。
- `packages/runtime`：沙箱宿主和组件接口。
- `packages/generator`：AI 生成组件、自检和修复原型，尚未集成进日常复习界面。
- `apps/web`：应用本身。
- `apps/desktop`：Electron 桌面端、打包配置和桌面集成测试。
- `apps/prototype/magazine`：M2 界面重设计的杂志风原型（数据写死），部署在 https://magazine.wengu.dev。
- `apps/prototype/game`：游戏风界面原型（真实排期，数据存在浏览器里），部署在 https://game.wengu.dev；`apps/web` 的界面按它的风格改过。

## 当前开发状态

M0 的导入导出、排期、沙箱和生成原型已实现。真实热门卡组（Ultimate Geography、MCAT、日语核心词汇等）的导入、渲染和导出往返已用 Anki 官方库逐项对照，结果一致；对照脚本是 `corepack pnpm --filter @wengu/anki verify:real <卡组路径>`。
M1 的导入、复习、浏览编辑、统计、导出和本地持久化已实现，连续两周自用验收尚未完成。
5 万笔记卡组上评分到显示下一张卡的延迟 P95 约 60 毫秒，达到 100 毫秒以内的目标。
Linux AppImage 和 deb 已构建，AppImage 已运行验证。macOS（Apple 芯片和 Intel 分开打包）和 Windows 安装包由 GitHub Actions 构建；macOS 包只有临时签名、未公证，Apple 芯片版在 CI 中验证过可以启动，Intel 版和 Windows 版尚未在真机上运行。
桌面端暂不支持自动更新。桌面数据位置、运行限制和完整命令见 [apps/desktop/README.md](apps/desktop/README.md)。
M2 的界面重设计有两个方向的原型：`apps/prototype/magazine`（杂志风，数据写死）和 `apps/prototype/game`（游戏风，用应用的排期代码，可以真实复习）。`apps/web` 已按游戏风改版：顶栏代替侧栏，首页是今日复习、卡组卡包、未来两周和记忆状况几个区块，复习页和其余页面换成同一套视觉；原型里的热力图和记忆稳定性需要核心统计接口提供按天的复习历史，还没有做。

在仓库根目录运行：

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm typecheck
corepack pnpm --filter @wengu/web dev
corepack pnpm --filter @wengu/desktop dist:linux
```
